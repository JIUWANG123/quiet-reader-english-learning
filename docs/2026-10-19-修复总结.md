# Quiet Reader 2026-10-19 修复总结

## 结论

本轮从交接文档的剩余问题出发，完成了 P1-P5 的功能修复和 P6 的清理收口：

- EPUB 阅读始终只保留一个 WebView，滑动、点击、滚动三种模式不再创建邻居 epub.js 实例。
- 左右滑动恢复了短促的方向滑入/淡入动画，仍然只有一个 WebView。
- 章节快捷跳转、8MB 大书重开恢复、同名书重新导入均已通过真机验收。
- 搜索改为复用导入生成的章节索引，并处理了 Gone Girl 的 spine href 差异和文本 offset 差异。
- 导入核心具备正式测试，重新导入事务失败不会删除原书文件。
- 导入后的隐藏预热 WebView 已移除，首次打开由当前阅读 WebView 生成 locations。

## 关键改动

### 1. 单 WebView 与翻页

- `EpubReader` 只渲染 `pool.current`，不再挂载 previous/next。
- 滑动模式使用库自带 `enableSwipe`；点击、音量键和滚动继续走 `paper.turn` + `goNext/goPrevious`。
- `epubPageMotion` 在单 WebView 内为翻页后的新页添加 160ms、24px 方向滑入和 0.9→1 淡入；遵守 `pageAnimation` 和系统减少动态效果设置。
- `qrInteractionBlocked` 和选区锁继续阻止翻页误触。

### 2. 位置恢复

- 保存的 CFI 落在重新分页后的页边界之外时，允许同章节页面被接受。
- 极端情况下回退到目标章节起点，避免大书直接报 `RESTORE_ANCHOR`。
- 8MB `Lord of the Mysteries` 的保存 CFI 已用真实 epub.js 回放验证。

### 3. 导入与数据保护

- 抽出 `importAsset.ts`，picker 和 Expo 文件系统留在 `import.ts` 适配层。
- 重新导入先把旧文件复制为 `.backup`；数据库事务成功后才删除备份。
- 文件复制显式使用 `overwrite: true`，修复 `Destination already exists`。
- 删除导入后的 `startEpubWarmup`、`EpubWarmupHost` 和预热模块。
- 新增 TXT、EPUB、EPUB 索引失败降级、事务失败恢复旧文件、成功重导入测试。

### 4. 搜索

- 搜索优先读取导入生成的 `.epub-index.json` 和章节缓存；缺失时才用 `buildEpubIndex` 重建。
- 搜索结果增加 `href`，EPUB 跳转按规范化路径后缀匹配 epub.js spine href，匹配不到才回退到章节序号。
- 索引 offset 与真实章节文本不一致时，按命中词和前后文选择最近匹配。
- 搜索缓存切换到 `search-v2.db`，首次搜索会重新建立索引。

### 5. 清理

- 移除旧 EPUB 邻居池的 rotation/invalidation 代码。
- 移除 `PageStackHandle.setReadiness`；TXT 继续使用 `NativePageStack` 的 `turn`。
- 删除 `TxtReader.tsx.ok`，忽略 `qr-import.txt`。
- 删除预热相关源文件。

  - 无结果搜索正常。

## 已知限制

1. **旧 WebView 卸载日志**：模式切换或退出时 Chromium 仍可能记录旧 renderer 的 `crash detected` 日志；当前 WebView 没有触发 `onRenderProcessGone`，也没有 `webview-unresponsive`，阅读会话稳定。要彻底消除，需要进一步改成跨模式复用同一个 WebView，属于生命周期重构，本轮未做。
2. **大书首次打开耗时**：8MB 书首次打开约 5 秒，已满足当前预期；未来若优化，应优先处理 locations 生成和首次布局，而不是重新引入邻居 WebView。
3. **搜索 offset 容错**：当索引文本和 live DOM 的空白/实体偏移不同，会按命中词与前后文选择最近匹配；重复词非常密集时仍依赖上下文区分。
4. **发布包**：本轮真机使用的是同签名 debug 包，尚未重新生成 release APK；发布前需要提交、push 并走 GitHub Actions。
