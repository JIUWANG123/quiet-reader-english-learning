# 翻页卡顿修复验收（2026-09-16）

状态：进行中；APK 仅在原生验收、验签后交付。

## 已确认的问题与处理

- 用户诊断含 1.10.2/1.11.0 数据，有重复 progress/saved 和 PREVIEW_STEP；日志缺请求起点，不能仅凭它断定 SQLite 阻塞手势。
- 原预览需要 CFI redisplay 和固定轮询等待；现在先尝试同章节同布局 visual anchor，并立即验证位置。宽高、章节或翻译布局变化时拒绝复用。
- 拖动中的手势捕获了旧 ready 值：预览已完成仍回弹。UI 线程共享状态让当前手势读取最新 readiness；同时测试失效后不得提交旧预览。
- 隐藏 WebView 冷启动时分配新 revision，onReady 曾错误标为已执行。现在启动后补发最新 pending navigation；同 revision 不重复执行。
- preview revision、取消标志、动画 epoch 和超时恢复阻止迟到结果覆盖当前页。中断动画释放 busy/interaction，恢复后旧动画不能提交。
- 进度保存相同位置去重、350ms 合并、串行 last-write-wins；最终 flush 写恢复日志。SQLite save 不在翻页提交 await 链上。
- 隐藏页同布局 scrollTo 后读回坐标立即校验，不再重复等待呈现帧；保留最终绘制确认后才允许翻页。

## 未采用的实验

动画期间提前复用远端页的实验在原生测试出现超时，已撤回；模型测试通过不能代替原生验收。软件 GPU 与资源争用也是影响变量，因此不声称已单独证明该实验是全部退化原因。

## 最终结果

待填写 APK 哈希、原生延迟和回弹情况。不得将之前同版本候选包当作最终包。
- 主机 GPU 有效 100 次压力测试：97 次手势、预览 p50 155ms / p95 229ms / max 437ms，无 preview-error；仍有 30 次 PREVIEW_PENDING。逐条时间线确认，多次 ready 已到达 20–50ms，松手仍读取未就绪，React 提交是剩余延迟之一。
- 新修复：绘制消息通过 PageStackHandle 直接同步 UI 线程 readiness，不等待 React 重渲染；来源 pageKey 校验拒绝旧页面消息，按钮与滑动使用同一实时状态。新增无重渲染解锁/旧页面拒绝用例，均通过；96 项完整回归通过，原生验证进行中。
